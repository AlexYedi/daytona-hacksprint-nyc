# Memory you can finally trust.

[Start in Studio](https://studio.surrealdb.com/current/contexts)[Technical deep-dive](/agent-memory/deep-dive)[View the benchmarks](/agent-memory/benchmarks)

**Provenance.** Every fact keeps its history, its permissions and its source, in one database.

**Retrieval.** Seven signals fuse into one ranking, and the trace records each one.

**One engine.** Memory in the database, not beside it: each fact and its edges in one transaction.

THE PROBLEM

## Where agent memory fails

### Memory ends with the session.The work is done again.

The context window is an agent's only built-in memory. When the session closes, so does everything it learnt.

### Retrieval returns both facts.The old one and the new.

A vector store appends. When a fact changes, both versions score well and nothing says which won, so the model guesses.

### Every question is asked again.A repeat costs as much as the first.

Retrieval plus an LLM call on every question charges the same for a repeated question as for a new one, even when no fact behind it has changed.

Agent Memory is not

a vector database

a chat-history blob

a hand-rolled knowledge graph

a context-window manager

an agent runtime

QUICKSTART

## From a context to a connected agent. Start in [Studio](https://studio.surrealdb.com/current/contexts), or read the [documentation](/docs/agent-memory).

1.  ### Create a context.Its own namespace and database.
    
    Open Studio, create a context and copy its URL and API key. A context is a tenant, and no API reads across contexts.
    
2.  ### Remember and recall.Every fact keeps its source.
    
    Install the client, export the connection details and write a fact. Recall returns it with its source.
    
3.  ### Connect your agent.Seven tools over MCP.
    
    Add the MCP server to Claude Desktop, Cursor or Claude Code, and the agent gets remember, recall, context, reflect, forget, upload and inspect.
    

CLI

### Install and remember

Install the agent-memory client, export the context's URL, key and ID, then write a fact and recall it with its source.

Copy

curl \-fsSL https://download.surrealdb.com/agent-memory/install.sh | sh  
  
export SPECTRON\_URL\="<context-url>"  
export SPECTRON\_API\_KEY\="<context-api-key>"  
export SPECTRON\_CONTEXT\_ID\="<your-context-id>"  
  
agent-memory remember "Sam joined Acme as principal engineer in 2024."  
agent-memory recall "what is Sam's role" \--json  

MCP

### Claude Desktop and Cursor

Add the context to the client's MCP configuration, and the agent gets the seven Agent Memory tools.

Copy

{  
  "mcpServers": {  
    "agent-memory": {  
      "url": "<context-url>/mcp",  
      "headers": {  
        "Authorization": "Bearer <context-api-key>",  
        "X-Spectron-Context": "<your-context-id>"  
      }  
    }  
  }  
}  

MCP

### Claude Code

One command registers the context's MCP server over HTTP.

Copy

claude mcp add \--transport http agent-memory "<context-url>/mcp" \\  
  \--header 'Authorization: Bearer <context-api-key>' \\  
  \--header 'X-Spectron-Context: <your-context-id>'

## Your questions,answered

Is this open source?

Not yet. SurrealDB, which stores every fact, is source-available under the Business Source License 1.1: free to use, modify and self-host, including in production, and the SDKs are open source under Apache 2.0 or MIT. The memory layer on top is closed source today. The one thing SurrealDB's licence reserves is running SurrealDB as a database service for third parties, where they create and manage their own schemas or tables. Each version becomes Apache 2.0 no later than four years after its release.

How was the benchmark measured?

Agent Memory scores 77.2% on BEAM at 1M, across the full 700-question set in 35 conversations. The full label is: BEAM · 1M, 35 conversations, 700 questions · official judge prompt, event ordering by Kendall tau · gemini-3.5-flash-lite judge · gemini-3.8-flash answering, gemini-3.7-flash extraction · October 2026. The score is the mean of ten memory abilities, and each ability's score is shown in the chart.

Where are the benchmark commands?

The [benchmarks page](/agent-memory/benchmarks) describes the harness's three steps: ingest the 1M conversations, answer every question and re-score the recorded answers. It also links the BEAM paper. The harness lives in the Agent Memory repository, which is private today, and the exact invocation behind the published run was not recorded. We will publish the commands beside the answers file.

What models can I use?

Extraction, reconciliation and answering call a language model, and the provider is selected per deployment: SurrealDB selects it on SurrealDB Cloud, and you choose it in your own cloud account or when self-hosting. The embedding model is gemini-embedding-2 at 3072 dimensions. Enterprise deployments can run local models instead, including air-gapped.

What leaves my machine?

LLM calls go to whichever provider the deployment uses. By default, embedding calls go to Google, because the embedder is gemini-embedding-2; an Enterprise deployment that runs local models, including an air-gapped one, sends its model calls to servers it chooses. Everything else stays yours: the database, the facts, the traces and the object-store originals live wherever you run them.

You never delete anything?

Agent Memory removes a fact only when it is told to, and three operations are distinct here. Supersession replaces a fact for retrieval while keeping the old row with valid\_until set, so the chain stays queryable. Aging reduces how much weight a fact carries over time. Deletion is a separate, explicit forget verb that retires a fact so it is no longer recalled, and purge removes the history as well, which is what erasure requires.

How is this different from a vector database?

Agent Memory is a memory and knowledge layer, not a vector database: typed entities, attributes and relations with provenance on every row, supersession instead of overwrite, tri-temporal history, and retrieval that fuses seven signals into one audited ranking. Vectors are one of those seven signals.

Is there a hosted version?

Yes. Agent Memory runs on SurrealDB Cloud, and a context is created in [Studio](https://studio.surrealdb.com/current/contexts). It is priced in four tiers from $30 a month to Enterprise, under a free Sandbox plan with 3 million tokens to try it on - [see the plans](/pricing?product=agentMemory). The engine underneath, SurrealDB, is source-available under BSL 1.1 and free to self-host; the Agent Memory layer is closed source, as the first answer says.
